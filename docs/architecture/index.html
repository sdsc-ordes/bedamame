Bedretto Underground Laboratory · semantic layer over openBIS

Bedamame architecture

The lab records boreholes, sensors and installations in openBIS. Annotations say what each object type and field means; a dump through the openBIS API becomes RDF named graphs, passes a SHACL check, and answers SPARQL queries and RO-Crate exports.

The examples follow one thread: tilt meter TILT4 is installed in borehole BFE_D_31, whose mouth was staked out on 8 September 2024. Each openBIS collection is a graph, and objects link across collections by permId: the deployment names None, and the tilt-meter collection describes that same IRI as TILT4. People's names are replaced in the fixture.

Example questions

Which hydromechanical sensors serve FEAR-2, and how were they installed?just query hydromechanical-deployments

Data and the vocabulary's sensor-type hierarchy. The query asks for hydromechanical sensors and never names tilt meters.

SELECT ?sensor ?kind ?serial ?borehole ?depth_m ?coupling ?installed
WHERE {
    GRAPH gr:vocab {
        ?type skos:broader* bedv:sensor-type-hydromechanical ;
              skos:prefLabel ?kind .
    }
    GRAPH ?sg {
        ?s bed:sensorKind    ?type ;
           schema:name       ?sensor ;
           schema:serialNumber ?serial .
    }
    GRAPH ?g {
        ?depl a ssn:Deployment ;
              ssn:deployedSystem     ?s ;
              ssn:deployedOnPlatform ?bh ;
              bed:servesExperiment   ?exp ;
              bed:coupling           ?coup .
        OPTIONAL { ?depl bed:measuredDepth [ qudt:numericValue ?depth_m ] }
        OPTIONAL { ?depl bed:deployedOn ?installed }
    }
    GRAPH ?eg { ?exp a bed:Experiment ; schema:name "FEAR-2" }
    GRAPH ?bg { ?bh a bed:Borehole ; schema:name ?borehole }
    GRAPH gr:vocab { ?coup skos:prefLabel ?coupling }
}
ORDER BY ?sensor

Data, ontology labels and vocabulary labels. Each property is named by its ontology label, and each concept value by its vocabulary label.

SELECT ?property ?value
WHERE {
    GRAPH ?g { ?bh a bed:Borehole ; schema:name "BFE_D_31" ; ?p ?o }
    GRAPH gr:ontology { ?p rdfs:label ?property }

    OPTIONAL { GRAPH gr:vocab { ?o skos:prefLabel ?concept } }
    OPTIONAL { GRAPH ?tg { ?o a bed:TestBed ; schema:name ?testBed } }
    OPTIONAL {
        GRAPH ?g { ?o qudt:numericValue ?num ; qudt:hasUnit ?unit }
        BIND (CONCAT(STR(?num), " ", REPLACE(STR(?unit), "^.*/", "")) AS ?quantity)
    }
    BIND (COALESCE(?concept, ?testBed, ?quantity, ?o) AS ?value)
}

Where is the mouth of BFE_A_01 now?just query current-collar-position

Its latest survey: BFE_A_01 was planned, then staked out two weeks later. Each survey keeps its own date and surveyor, so the history stays.

SELECT ?borehole ?surveyType ?easting ?northing ?elevation ?surveyed
       (GROUP_CONCAT(?name ; separator=", ") AS ?by)
WHERE {
    GRAPH ?g {
        ?survey a bed:CollarSurvey ;
                bed:ofBorehole  ?bh ;
                bed:surveyType  ?type ;
                bed:surveyDate  ?surveyed ;
                bed:easting     ?easting ;
                bed:northing    ?northing ;
                bed:elevation   ?elevation .
        OPTIONAL { ?survey bed:surveyedBy ?agent }
    }
    GRAPH ?bg { ?bh a bed:Borehole ; schema:name ?borehole }
    GRAPH gr:vocab { ?type skos:prefLabel ?surveyType }
    OPTIONAL { GRAPH ?ag { ?agent schema:name ?name } }

    FILTER (?borehole = "BFE_A_01")

    FILTER NOT EXISTS {
        GRAPH ?later { ?other a bed:CollarSurvey ; bed:ofBorehole ?bh ; bed:surveyDate ?laterDate }
        FILTER (?laterDate > ?surveyed)
    }
}
GROUP BY ?borehole ?surveyType ?easting ?northing ?elevation ?surveyed
