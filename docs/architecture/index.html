Bedretto Underground Laboratory · semantic layer over openBIS

Bedamame architecture

Ontology, vocabulary and SHACL shapes for the lab's openBIS, where boreholes, sensors and installations are recorded. Each openBIS object type and field is annotated with an ontology term. A dump made through the openBIS V3 API is converted to RDF, one named graph per collection, validated with SHACL, and then queried with SPARQL or exported as an RO-Crate.

Example questions

  • Which hydromechanical sensors serve FEAR-2, and how were they installed? Uses the sensor-type hierarchy in the vocabulary, so tilt meters count as hydromechanical sensors. Needs the borehole and sensor links of the object-links change (05).
  • What do we know about borehole BFE_D_31? Lists every field with its label from the ontology, and every vocabulary value with its label. Without the test-bed change (02) and the vocabularies change (06) it lists fewer fields: no test bed, tunnel section, geometry, drilling style or status.
  • Where is the mouth of BFE_A_01 now? Takes the latest mouth survey, with its date and surveyor. Needs the survey objects of the mouth-surveys change (03).

The proposed openBIS changes

The 6 changes add fields and object types to the lab's openBIS and remove nothing: the old fields stay until the administrator retires them. Each change comes as a file to import, with a note on what it does to the data. More detail in changes.md.

  • 01 People. Names typed as text, such as "deployed by" or "operated by", become links to a list of people and organisations. Each person is entered once and can be found from everything they worked on.
  • 02 Test beds. Test beds are now a fixed list of names. They become records of their own, so a test bed can have a description, and boreholes link to their test bed.
  • 03 Borehole mouth surveys. Each planned or measured position of a borehole mouth becomes a record of its own, with its date, source and surveyor, so a new survey no longer overwrites the old one.
  • 04 Sensor positions. The same for the position of an installed sensor. None of the current installations has coordinates, so this starts empty.
  • 05 Object links. Installations, logging runs and cores point to their borehole, and installations to their sensor, instead of naming them in a text field. A link cannot be misspelt.
  • 06 Vocabularies. Text fields that only ever hold a few values, such as tunnel section or drilling style, become fields where you choose from a list, so each value is spelt one way. The five yes/no fields about where a sensor is installed become one such list.
